#+TITLE: nl-clj — a Clojure-compat persistent-data library for NeLisp

* Motivation

Doc 194 (=docs/design/194-clojure-compat-library.org=), build-first
Tier 1: a persistent vector, a persistent hash-map/hash-set, an
=atom=, and a minimal eager seq API, so NeLisp programs can write in a
Clojure idiom without giving up plain Elisp semantics anywhere that
does not opt in.  Doc 194 is a measured survey ("every asset claim
below was either read from a file at a cited line or measured directly
against a built =target/nelisp="), not a guess; this package follows
its decisions on naming, representation, and HAMT design exactly (one
small, documented representation refinement -- see
=src/nl-clj-core.el='s Commentary).

This is an *opt-in* extension library (Doc 168 section 2, the
convention every =nl-= package here follows): loading it changes
nothing about plain Elisp semantics.  It depends only on =nl-prelude=
(the =nl-error= condition every =nl-clj-error= derives from).

* Representation (Doc 194 §3.2)

Every collection is a plain Elisp vector whose slot 0 is a
distinguishing tag symbol, =nl-cell='s own idiom
(=packages/nl-safe/src/nl-safe.el=), NOT =cl-defstruct=/=record=:

#+begin_example
persistent vector: [nl-clj--pvec COUNT SHIFT ROOT TAIL]
persistent map:    [nl-clj--pmap COUNT ROOT]
persistent set:    [nl-clj--pset COUNT ROOT]
persistent list:   ordinary cons cells, nil-terminated (already
                    Clojure's own representation, no wrapper needed)
atom:              [nl-clj--atom VALUE WATCHES]
#+end_example

Why not =record=: Doc 194 §2.1 measured, against a built
=target/nelisp=, that records print with real Emacs =#s(...)= syntax
but do NOT round-trip through =read-from-string= on this substrate --
a genuine print/read asymmetry, not merely "records are unreliable."
Plain tagged vectors round-trip correctly (measured, same section).
=test/nl-clj-standalone-smoke.el= proves this holds for THIS package's
own representation specifically, on the real standalone binary, not
just claims it by analogy.

One small, documented divergence from Doc 194's own literal sketch:
sets use a distinct =nl-clj--pset= tag rather than sharing =pmap='s
(the doc's own text: "a map whose values are all the sentinel
=nl-clj--set-member="). A shared tag would make =nl-clj-map-p=/
=nl-clj-set-p= unable to tell a map from a set without walking every
value; a second tag costs nothing (both route through the identical
HAMT engine in =nl-clj-hash.el=). See =src/nl-clj-core.el='s
Commentary for the full reasoning.

Trie *internal* nodes (branch arrays inside a vector or a HAMT) are
deliberately untagged plain vectors/conses -- never handed to a caller
directly.

* API

** Atom (=nl-clj-atom.el=, Doc 194 §4.5)

#+begin_src elisp
(require 'nl-clj)
(let ((a (nl-clj-atom 0)))
  (nl-clj-swap! a #'1+)                     ; => 1
  (nl-clj-reset! a 10)                      ; => 10
  (nl-clj-compare-and-set! a 10 20)         ; => t, now 20
  (nl-clj-deref a))                         ; => 20
#+end_src

=nl-clj-swap!=/=reset!=/=compare-and-set!= are single-assignment, not
a compare-and-set retry loop -- NeLisp's current execution model has
exactly one thread of Lisp-level control (Doc 194 §2.7), so the retry
loop's entire reason to exist is absent; see =src/nl-clj-atom.el='s
Commentary for the full argument and the one honest divergence this
creates (F runs exactly once, always -- stronger than Clojure's own
"may retry" contract).  =add-watch=/=set-validator!= are named by Doc
194 §4.5 as real but peripheral -- deliberately not in this phase.

** Persistent vector (=nl-clj-vector.el=, Doc 194 §4.1)

32-way bit-partitioned trie with a <=32-element tail, matching
Clojure's own complexity/sharing contract: O(log32 N) =assoc=/=get=,
O(1) amortized =conj=/=peek=/=pop=.

#+begin_src elisp
(nl-clj-vector 1 2 3)                       ; construct from items
(nl-clj-vec '(1 2 3))                       ; construct from any seqable
(nl-clj-conj v 4)                           ; append
(nl-clj-assoc v 0 :x)                       ; index update (0..count legal)
(nl-clj-get v 0)  (nl-clj-nth v 0)          ; get: nil/default on OOB; nth: error
(nl-clj-count v)  (nl-clj-peek v)  (nl-clj-pop v)
(nl-clj-subvec v 1 3)
#+end_src

=nl-clj-subvec= is a deliberate divergence: an eager O(k) rebuild, not
Clojure's O(1) offset/end-aware view type (Doc 194 §4.1 explicitly
defers that optimization as separable future work; this package's own
brief asks for =subvec= in the API, so it ships correctness-first).

** Persistent hash-map / hash-set (=nl-clj-hash.el=, Doc 194 §4.2)

A real HAMT: bitmap-indexed branch nodes (the standard popcount-prefix
trick), collision buckets for keys whose hash agrees all the way to
=nl-clj-hash--max-shift=.  A set is the identical engine with values
ignored.

#+begin_src elisp
(nl-clj-hash-map :a 1 :b 2)
(nl-clj-assoc m :c 3)  (nl-clj-dissoc m :a)
(nl-clj-get m :a)  (nl-clj-contains? m :a)
(nl-clj-keys m)  (nl-clj-vals m)  (nl-clj-count m)

(nl-clj-hash-set 1 2 3)
(nl-clj-conj s 4)  (nl-clj-disj s 1)
(nl-clj-get s 2)  (nl-clj-contains? s 2)
#+end_src

Deliberate divergence: no small-map array-map special case (Clojure's
own =PersistentHashMap= flattens <=8-entry maps for cache-friendliness
before promoting to a true HAMT) -- always-HAMT here, correct but not
tuned for small maps; Doc 194 §8 leaves this an open question pending
real usage data.

This file deliberately does NOT use the standard-library =logcount=
for the popcount step Doc 194 §4.2 itself describes -- a repo-wide
grep found zero references to it anywhere in this tree, meaning
nothing has exercised it standalone.  =nl-clj-hash--popcount= is a
manual bit loop over =logand=/=ash=, both confirmed present in
=scripts/nelisp-standalone-build.el='s dispatch table.  "Measured, not
assumed," applied to a primitive choice, not only a fact claim.

** Seq API (=nl-clj-seq.el=, Doc 194 §4.7's minimal, eager slice)

Generic across vector, map, set, and plain Elisp lists (a plain Elisp
vector too, as a bonus that costs nothing given the dispatch):

#+begin_src elisp
(nl-clj-seq coll)  (nl-clj-first coll)  (nl-clj-rest coll)  (nl-clj-next coll)
(nl-clj-cons x coll)
(nl-clj-into to from)
(nl-clj-map f coll)  (nl-clj-filter pred coll)  (nl-clj-reduce f init coll)
(nl-clj-equal a b)   (nl-clj-hash x)
#+end_src

Eager, not lazy: =nl-clj-map=/=filter= return a plain Elisp list;
=nl-clj-reduce= walks with a plain =while= loop, not recursion --
stack-safe over an arbitrarily long seq for free, with no need for
=nl-loop=/=nl-recur= (those are load-bearing for Doc 194 §4.7's
*deferred* lazy-seq walk, not for an already-eager one).

A named, documented divergence from Clojure: =nl-clj-rest= and
=nl-clj-next= are behaviorally identical here.  Real Clojure's own
distinction only exists because it separates an empty-but-not-=nil=
=()= from =nil=; this package's seq representation IS a plain Elisp
list, where empty is always literal =nil= -- there is no distinct
"empty, not nil" seq object to make the two functions diverge.  Both
are still defined, under their own names, for full API-surface parity.

=nl-clj-equal=/=nl-clj-hash= exist because plain =equal=/
=sxhash-equal= walk a tagged vector *structurally* (comparing
ROOT/TAIL/SHIFT element by element), which is a different question
from Clojure's own logical collection equality (comparing the
*sequence of elements*, regardless of internal tree shape -- Doc 194
§3.2's own named correctness trap).  A named, accepted footgun this
does NOT solve: passing an nl-clj collection as a key into a *plain*
=(make-hash-table :test 'equal)= silently uses the wrong notion
(tree-shape, not content) -- =define-hash-table-test= is void-function
on this substrate (Doc 194 §2.3), so there is no way to register the
right one as a real hash-table =:test= at all.

* Naming (Doc 194 §3.1)

Every public symbol is =nl-clj-= prefixed.  Elisp already has
=assoc=/=get=/=pop=/=atom=/=concat= with different meanings (Doc 194
§2.6's measured collisions); this package never shadows them.

=nl-ns-in= sugar (=packages/nl-ns=) is optional, demonstration-only,
and never required to call any function here directly:

#+begin_src elisp
(require 'nl-ns)
(nl-ns-define nl-clj :prefix "nl-clj-"
  :members (conj dissoc get into count seq first rest
            swap! reset! compare-and-set!))
(nl-ns-in nl-clj
  (defun demo (v) (conj v 1)))   ; expands (conj v 1) to (nl-clj-conj v 1)
#+end_src

=assoc=, =get=, =pop=, =atom=, =concat= are deliberately never listed
in a =:members= block -- =nl-ns-in='s whole-body rewrite (Doc 194
§2.6) would otherwise silently redirect a plain Elisp =(atom x)= call
site inside the same block to =nl-clj-atom=.  This package still
exports =nl-clj-assoc=/=nl-clj-get=/=nl-clj-atom=/etc. as ordinary
qualified names either way; only the bare-name sugar for these five
specific names is withheld.

* Errors

=nl-clj-error= (parent, derives from =nl-prelude='s =nl-error=),
=nl-clj-index-error= (out-of-bounds =nth=/=assoc=/=pop=/=subvec=),
=nl-clj-type-error= (wrong collection type for the operation).

* Next phases (Doc 194 §5/§6, out of scope this phase)

- *Transients* (§4.4): reuses =nl-safe='s =nl-cell= borrow-cell fence
  as the mutability boundary and the "freeze forever" =persistent!=
  trick -- no new checking mechanism needed, cheap once §4.1/§4.2 have
  callers to make transient.
- *Channels and =go= blocks over =nelisp-actor=* (§4.6): parking
  =chan=/=close!=/=go=/=>!=/=<!= are thin wrappers over already-
  standalone-proven =nelisp-actor= primitives; =>!!=/=<!!=/=alts!= are
  real new plumbing, ranked last within Tier 1.
- *Lazy sequences* (§4.7's deferred half): memoized =lazy-seq= over
  =nl-cell=, reusing the identical borrow-fence trick a second time
  for a different purpose (reentrant-force protection).
- *Refs/STM* (§5.1) and *true multicore* (§5.2): explicitly NOT
  recommended for this library's own roadmap (Doc 194's own verdict)
  until a real second thread of Lisp-level execution and a concurrent-
  safe GC story exist -- building either now would be a facade, not
  infrastructure.

* Testing

Host Emacs (part of =make test= at the repo root; the root Makefile
globs =packages/*/test/nl-*-test.el=):

#+begin_src sh
emacs --batch -Q -L packages/nl-prelude/src -L packages/nl-clj/src \
  -L packages/nl-clj/test \
  -l ert -l nl-clj-atom-test -l nl-clj-vector-test \
  -l nl-clj-hash-test -l nl-clj-seq-test \
  -f ert-run-tests-batch-and-exit
#+end_src

Standalone NeLisp (no Emacs, no ert -- a minimal shim runs the same
test bodies; dependencies are loaded by explicit path, matching
=nl-safe=/=nl-prelude='s own smoke runners):

#+begin_src sh
./target/nelisp --load packages/nl-clj/test/nl-clj-standalone-smoke.el
#+end_src

The standalone smoke additionally proves the specific claim this
package's representation choice depends on: it =prin1=/=read-from-
string='s a persistent vector on the live binary and asserts the
result is =equal= to the original AND still behaves as a working
vector afterward -- the exact property Doc 194 §2.1 found =record=
lacks on this substrate.
