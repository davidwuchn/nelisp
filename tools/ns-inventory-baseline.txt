# nl-ns namespace-boundary baseline (tools/nl-ns-inventory.el).
# One "KIND COUNT" line per tracked finding kind.  Raise a number only
# in the commit that introduces the finding; lower it whenever the
# ratchet notice says you can.
#
# ns-collision-divergent is the actionable half: the definitions differ,
# so which behaviour you get depends on load order.  ns-collision is the
# benign half: same definition in two places.
#
# 2026-08-17 catch-up.  This gate was never wired into CI, so nobody ran
# it between 2026-08-15 and today and every number below had drifted:
#
#   ns-collision            275 -> 148   (-127, captured)
#   ns-collision-divergent  114 ->  97   ( -17, captured)
#   ns-prefix-violation     853 -> 848   (  -5, captured)
#   ns-private-escape       526 -> 611   ( +85, conceded)
#
# Four of the five move in the tightening direction and are locked in
# here, so they cannot grow back.  The fifth is conceded rather than
# fixed: the escapes are concentrated -- 352 of the 611 are in
# scripts/compile-elisp-objects.el (242) and
# scripts/nelisp-standalone-build.el (110), with
# lisp/nelisp-aot-compiler.el next at 40 -- and unpicking a private-name
# boundary inside the build path is a change that wants its own commit
# and its own verification, not a drive-by.
#
# The step that keeps this honest went in with the same commit:
# ns-inventory now runs in CI beside unsafe-inventory.  A drift of 85
# findings should not have been able to accumulate unnoticed, and from
# here it cannot.
#
# 848 -> 850 on 2026-08-19.  `nl-ns-accepted-note' and
# `nl-ns-unnoted-accepted' are two new public entry points in
# packages/nl-ns/src/nl-ns.el, added so the accepted-divergence file can
# carry a per-entry reason.  All 25 of that file's public functions are
# counted here, the 23 that predate today included: the check wants
# `nl-ns--' for every name that is not the feature name itself, so what
# it measures in practice is public API surface, which is most of what
# the 848 is.
#
# Renaming them was measured rather than assumed, and does not remove the
# finding -- it moves it:
#
#   nl-ns-  (as committed)   prefix-violation 25   private-escape 0
#   nl-ns--                  prefix-violation 23   private-escape 1
#
# because scripts/nl-ns-gate.el calls one of them across the boundary.
# That trades two findings in the kind this file is tightening (853 ->
# 848) for one in the kind it concedes (611, growing).  The two names
# also belong to a family -- load-accepted, write-accepted,
# stale-accepted, unaccepted -- that is public single-dash throughout,
# and splitting the family's naming to move a number is the wrong way
# round.
# 148 -> 149 on 2026-08-19: `nelisp--path-split', the component splitter
# `expand-file-name' needs.  It is duplicated into lisp/nelisp-stdlib-misc.el
# beside the `expand-file-name' that calls it, because leaving it only in the
# prelude made that file reference a private name it does not define -- an
# ns-private-escape, which is the finding kind this tree is conceding rather
# than tightening.  A benign same-definition collision in the kind that is
# tightening is the better of the two, and it matches what the file already
# does: `expand-file-name' itself is duplicated there on purpose, and both
# copies now carry a note saying `make ns-gate' polices the drift.
# 149 -> 150 on 2026-08-19: `compare-strings'.  It existed only in
# lisp/nelisp-stdlib-plist-str.el, which the standalone does not load, so it
# was `void-function' at runtime -- the body was fine and simply in the
# wrong place.  Moving a copy to the prelude makes it exist where it runs;
# the two are byte-identical, so this is the benign same-definition kind and
# ns-collision-divergent stays at 97.
# 150 -> 152 on 2026-08-19: `lsh' and `copy-sequence'.  `lsh' did not exist
# in the standalone at all (void-function) and lisp/nelisp-stdlib-misc.el
# aliased it to `ash', which is a different operation -- a right shift of a
# negative value fills with the sign bit there and with zeros here.  Both
# files now carry the real definition, byte-identical, so this is the benign
# same-definition kind.
# 152 -> 156 on 2026-08-19: `print-length', `print-level',
# `nelisp--prn-depth' and `nelisp--prn-symbol-needs-leading-escape-p'.  The
# printer gained `print-length'/`print-level' support and a symbol escaper
# that looks at the whole name, and lisp/nelisp-stdlib-prn.el carries the
# same bodies so the two do not drift.  Same-definition, so benign.
ns-collision 156
# 97 -> 96 on 2026-08-19: `string-equal' no longer differs between the two
# files -- the prelude's now signals for a non-string instead of falling
# through to `equal', and the lisp copy was brought with it.  Ratcheted down
# rather than left, since the gate offered.
ns-collision-divergent 96
# 850 -> 851 on 2026-08-19: `nl-check-file-quoted-unsafe', the entry point
# that reports the unsafe calls inside quoted forms.  Same situation as the
# nl-ns pair above -- it is public because tools/nl-check-inventory.el calls
# it across the boundary, and naming it `nl-check--' would move the finding
# into ns-private-escape rather than remove it.
# 851 -> 853 on 2026-08-19: the same four names, counted again under the
# prefix rule -- `print-length' and `print-level' are Emacs's names and
# cannot carry a `nelisp--' prefix, and the two helpers do carry it but are
# not the feature name itself, which is what this check asks for.
ns-prefix-violation 853
ns-private-escape 611
ns-unreadable 0
