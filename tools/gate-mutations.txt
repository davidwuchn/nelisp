# Known-defect injections (tools/nelisp-gate-mutation.sh).
#
# Each row is: GATE | FILE | SED-EXPRESSION | WHAT IT BREAKS
#
# The row is applied with `sed -i', the gate is run, and the file is
# restored.  The gate MUST fail.  A gate that stays green with a real defect
# in front of it is not a gate, and on 2026-08-19 three of them were in
# exactly that state while printing PASS.
#
# Keep the injections small and obviously wrong.  A subtle one that a gate
# legitimately does not cover teaches nothing except to delete the row.
emacs-parity|scripts/nelisp-stdlib-prelude.el|s/^(defun regexp-quote (s)/(defun regexp-quote (s) (setq s (concat s "@"))/|regexp-quote appends a stray character
ns-gate|scripts/nelisp-stdlib-prelude.el|s/^(defun round (x \&optional div)/(defun round (x \&optional div) (setq x x)/|round diverges from its lisp/ mirror
# The replacement is GLOBAL on purpose.  The first version changed one
# occurrence of a name that appears ten times, so the name stayed covered and
# the gate correctly stayed green -- a weak injection reads as a broken gate.
# The injection has to remove a name the corpus mentions ONCE.  An earlier
# version renamed `regexp-quote', which the corpus has grown many uses of --
# the coverage count stayed above the baseline and the gate correctly stayed
# green, which reads as a broken gate.  `nbutlast' is mentioned once.
# The name has to be one the compat table LISTS and the corpus mentions
# ONCE.  Two earlier versions failed that: `regexp-quote' is mentioned many
# times (the count stayed above the floor), and `nbutlast' is not in the
# generated table at all (so it was never counted, and removing it changed
# nothing).  Both read as a broken gate when the gate was fine.
parity-coverage|test/nelisp-shadow-differential-cases.el|s/generate-new-buffer/ignore-me-not-a-name/g|a covered name stops being mentioned
prelude-toplevel-check|scripts/nelisp-stdlib-prelude.el|s/^(defun string-empty-p (s) (string-equal s ""))$/(defun string-empty-p (s) (string-equal s ""))\n  (nelisp--check-string s)/|a check lands outside a one-line defun
# The sed expression cannot use `|' -- it is this file's field separator.
prelude-toplevel-check|scripts/nelisp-stdlib-prelude.el|/^  (defun seq-length (seq) (length seq)))$/a\    (unless (sequencep seq) (signal (quote wrong-type-argument) (list (quote sequencep) seq)))|a check lands outside a one-line defun INSIDE an unless wrapper

# added to unsafe-inventory, ns-inventory, fallback-inventory and pkg-graph,
# plus generated-source-parse, which had no row at all.  Each is chosen so a
# bare COUNT would not have moved: the pinned identity changes (a new one
# appears, or an already-divergent pair's shape drifts) while the aggregate
# stays where it was, which is exactly the blind spot `parity-coverage' and
# `ns-gate' were caught in on 2026-08-21.

# 2026-08-22 (this session): ert-full had never been mutation-proven --
# `nelisp-ai.sh test' is not a raw `make' target, so it could not go
# through this file's plain `make "$gate"' runner unmodified; fixed in
# `tools/nelisp-gate-mutation.sh' with a small `ert-full'-specific branch
# that calls `nelisp-ai.sh test' instead (see its comment for both rows'
# routing and why each one's report is scratched to a throwaway
# NELISP_GATE_DIR rather than overwriting the tree's real ert-full
# report).  Two rows, the two cases named in the survey this session
# closed gaps from:
#
#   the corrupted-helper row targets `nelisp-eval' (src/nelisp-eval.el),
#   the single most widely-used repo-defined function in the whole test
#   tree (the interpreter entry point nearly every `(should (equal
#   (nelisp-eval FORM) ...))' assertion depends on) -- made to always
#   return nil regardless of FORM.  Running the FULL suite to prove this
#   costs about 75s per injection, too slow for `gate-mutation' inside
#   `nelisp-ai.sh check''s fast lane; scoped via
#   NELISP_GATE_MUTATION_TEST_FILES to `test/nelisp-eval-test.el' alone,
#   which calls `nelisp-eval' directly and fails within a couple of
#   seconds once corrupted -- the SAME `run_ert_gate' path `ert-full'
#   uses for real, exercised on fewer files, not a different mechanism.
#
#   the empty-glob row targets `test_files()' itself
#   (tools/ai/nelisp-ai.sh), the function `cmd_test' calls to build
#   ert-full's file list -- corrupted so its output is filtered to
#   nothing regardless of what matched, the same "glob defined no test"
#   shape AI.md's rule 1 already documents.  This one must run UNSCOPED
#   (no NELISP_GATE_MUTATION_TEST_FILES): scoping would skip the very
#   line being tested.  `run_ert_gate' already had the guard that catches
#   this -- an empty file list reports GATE-COUNT ran=0 failed=1 and
#   exits 1 before spawning Emacs at all -- so this row is also the
#   cheapest of the two, proving a pre-existing guard rather than
#   exercising the interpreter.
ert-full|src/nelisp-eval.el|s/^  (nelisp-eval-form form nil))$/  (progn (nelisp-eval-form form nil) nil))/|nelisp-eval always returns nil, corrupting every should that reads its value
ert-full|tools/ai/nelisp-ai.sh|s/'nelisp-worker-soak-test\\\.el\$'/'.'/|test_files() output gets filtered to nothing regardless of what matched; "no test file matched" must still fail ert-full

# 2026-08-23 (this session): gate-selfcheck itself had no row -- fixed while
# making it skip-aware (fix/gate-selfcheck-skip-aware), which changed how it
# tells a reasoned `GATE-SKIP' apart from a gate that prints NEITHER a count
# NOR a skip reason, i.e. the exact "PASS while seeing nothing" shape this
# gate exists to catch.  `bootstrap-contract' is the injection target: its
# GATE-COUNT print is a single line, so the sed match is unambiguous, and
# dropping it (replaced with `nil', paren-balanced -- the form it replaces
# opens and closes exactly two parens) leaves the rest of the gate's checks
# running and printing "ok"/"PASS" as before -- a silent, fully-fake pass,
# not a crash.  Confirmed by hand before this row was added: mutated,
# `make bootstrap-contract' exits 0 with no GATE-COUNT line, and
# `make gate-selfcheck' (real Emacs 30.x, no skip in play) correctly goes
# red on it.
gate-selfcheck|tools/nelisp-bootstrap-contract.el|s/^    (princ (format "GATE-COUNT checked=%d findings=%d.*missing))$/    nil/|bootstrap-contract fake-passes (prints ok/PASS, no GATE-COUNT line); gate-selfcheck must still flag it as a finding, not confuse it with a reasoned skip
