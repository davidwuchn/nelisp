# Unsafe-surface baseline (tools/nl-check-inventory.el, Doc 170 sec 4.3).
# The count is calls to a `nl-safe-unsafe-primitives' name made outside an
# `nl-unsafe' block, across lisp/ and scripts/.  Raise it only in the commit
# that introduces the calls, and say here what they are.
#
# 318 -> 369 on 2026-08-19, and the two halves of that +51 are different
# things, so they are recorded separately rather than as one number:
#
#   +10  new code.  `nelisp-standalone--reader-posix-env-forms' walks the
#        Linux entry stack at boot to publish the process environment,
#        which is what arms the Doc 170 sec 5 checked allocator -- see that
#        section's 2026-08-19 note.  Raw loads are the whole point of the
#        function: it reads argc, then a NULL-terminated envp vector, then
#        NUL-terminated bytes, none of which exists as anything but memory
#        at that moment.  Measured alone: 10 findings.
#
#   +41  code that was already there and that this gate could not see.  The
#        two Linux arms of the per-target OS forms were quoted lists, and
#        quoted forms are not scanned by design (the rule exists so the AOT
#        grammar data is not mistaken for code).  Splicing the walker in
#        turned them into backquotes, and 41 pre-existing calls -- 32 of
#        them `syscall-direct' in nl_os_open_read and friends -- became
#        visible.  Measured by taking the file at HEAD and changing nothing
#        but those two quotes: 295 -> 336.
#
# The second half is the interesting one: this gate has been reporting the
# per-target OS layer as clean because of how the layer is written, not
# because of what it contains.
#
# 369 -> 531 on 2026-08-19, chasing that down.  Two causes, measured apart:
#
#   +59  a defect in the scanner, not new code.  `nl-check--unsafe-scan'
#        walked only the cdr of a form, so anything in car position was
#        never looked at.  A `let' binding list is (BINDING ...) with
#        BINDING a cons, which put every first binding's initialiser in
#        exactly that blind spot -- and allocating in the first `let*'
#        binding is the house idiom of the standalone build.
#        `(let ((x (alloc-bytes 1 1))) x)' scanned as clean.  Fixed, with
#        four regression tests; the tree went 369 -> 428 with no code
#        change at all.
#
#  +103  the per-target OS layer, now visible.  Five pcase arms across
#        `nelisp-standalone--reader-os-base-forms' and
#        `nelisp-standalone--os-syscall-xlat-forms' were quoted lists and
#        so were skipped whole; their siblings were backquotes and so were
#        counted.  Nothing but the quote character decided whether a
#        target's syscall layer appeared in this number.  The five are
#        backquotes now, which is value-identical when the template has no
#        unquote -- checked structurally rather than assumed: 13
#        quote/backquote nodes compared across both generators, all equal,
#        none of the converted ones carrying an unquote.
#
# What is still excluded, and why the gate now says so out loud: this tree
# writes its runtime as quoted generator bodies -- (defconst
# nelisp-cc-...--source '(seq (defun ...) ...)) -- and the scan steps over
# quoted forms by design.  That rule is right: it is what keeps opcode
# tables like (ptr-read-u16 . 39) and name lists out of a count of calls.
# But it also means 4607 unsafe-primitive calls across 85 files sit outside
# this number, 2182 of them in the standalone build script alone.  The run
# prints that tally and the files it falls in, so 531 is never read as the
# unsafe surface -- it is the part of the surface written outside a quote.
#
# Gating the other 4607 is a policy question this file does not settle.
# The two candidate rules were both measured: descending into every quoted
# form counts 49 opcode-table and name-list entries in
# lisp/nelisp-aot-compiler.el that are not calls, and restricting it to
# quoted forms containing a `defun' drops 11 of those but loses 78 real
# ones in the build script.  Neither is clean, which is the argument for
# reporting the number rather than pretending a heuristic settles it.
# 531 -> 538 on 2026-08-19: `nl_os_getcwd', the getcwd(2) wrapper that lets
# `default-directory' be bound to the real working directory.  It was

# `(expand-file-name "a")' answered "/a".  Raw syscall and raw buffer are
# the whole content of the function: it asks the kernel for a path and
# copies bytes.  $PWD was available and deliberately not used; being right

# 538 -> 562 on 2026-08-22: the standalone-reader input-hardening fix, all

# already uses -- no new kind of unsafe call, more call sites of the kinds
# already present.
# 562 -> 590 on 2026-08-23: Doc 180 Phase 1 (form-located errors), all in
# `scripts/nelisp-standalone-build.el' (538 -> 566 for that file, measured
